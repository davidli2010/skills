# 核心操作详解

> **触发词参考**：摄入="导入/处理资料/添加到知识库/ingest"；查询=对知识库提问或要求分析；检查="检查知识库/维护一下/lint"。
>
> **OKF 对齐**：页面写入遵循 `schema-design.md` 的 frontmatter 五大家族（type / provenance / trust / lifecycle）；日志与索引遵循 `indexing.md`。

## 1. 摄入（Ingest）

当新资料添加到 `raw/` 时，按以下工作流处理：

1. **阅读**完整的源文档（如有图片也一并读取）。
2. **讨论**与人类交流关键要点（如果人类希望参与）。
3. **撰写来源摘要页**（`type: Source Summary`），放入 `wiki/sources/`，在 `sources[]` 中登记原始资料路径与 id。
4. **更新 `index.md`** — 添加条目，摘要取自页面 `description`。
5. **扫描 wiki** 中所有相关页面，执行增量更新：
   - 用新信息更新实体页（`type: Entity`）
   - 用新视角或数据更新概念页（`type: Concept`）
   - 标记新旧信息之间的矛盾（标注来源与日期）
   - 在相关页面之间添加交叉引用（相对于当前页面的 Markdown 链接）
   - 如果来源引入了新实体/概念，则创建新页面
6. **追加到 `log.md`**，格式见 `indexing.md`（`## YYYY-MM-DD` + 加粗引导词）。

**frontmatter 纪律**：
- 所有新页面/更新页面补全 `generated: { by: "llm-wiki/<model>", at: ... }`。
- 来源登记到 `sources[]`（每个原始资料一个条目，`resource` 指向 `../raw/xxx.md`）。
- 正文事实性论断用 footnote keyed to `sources[].id` 归因。
- 校准期（前 5-10 个来源）人工确认摘要后，补 `verified: { by: "human:<id>", at: ... }`。
- 写入完成后按 `schema-design.md` 的「OKF 合规自检清单」自检（type 非空、frontmatter 可解析、footnote label 命中 `sources[].id`、actor 约定、保留文件名用途等）。

**导入规模预期**：
- 初期（wiki < 20 页）：一篇中等文章（2000-3000 字）通常新建 2-4 个页面，更新 2-4 个已有页面，总计触及 5-8 个文件。
- 成熟期（wiki > 50 页）：同样一篇文章可能触发 10-15 个页面更新，因为关联更多。

**注意事项**：
- 建议前 5-10 个来源逐个处理，全程有人类参与（这是校准期）。
- 当 schema 和工作流稳定后，可以批量处理。
- 摄入时偏好逐个处理并全程参与——阅读 LLM 写的摘要、检查更新、引导 LLM 该强调什么。

## 2. 查询（Query）

针对 wiki 回答问题：

1. **先读 `index.md`**，找到相关页面。
2. **深入阅读**已识别的页面，获取详细内容。
3. **综合回答**，附带指向 wiki 页面和原始来源的引用；**标注引用页面的信任层级**（由 `verified` 推导）：
   - `human-reviewed`（含 `human:<id>` 验证）
   - `machine-confirmed`（仅非 `human:` 验证）
   - `unverified`（无验证）
4. **注意时效性**：若引用页面的 `stale_after` 已过（`today >= stale_after`），主动提示"内容已过期"。
5. **选择合适的输出格式**：
   - Markdown 文档用于叙述性回答
   - 对比表格用于比较类问题
   - Marp 幻灯片用于演示需求
   - 图表（matplotlib）用于数据可视化需求
   - Canvas 用于关系图谱

**关键洞察**：好的回答应该作为新页面反哺 wiki。一个对比分析、一个综合总结、一个在查询中发现的关联——这些都是有价值的知识，应该在 wiki 中累积，而不是消失在聊天记录里。每次查询都是 wiki 的潜在贡献。反哺页面同样遵循 frontmatter 五大家族。

## 3. 检查（Lint，健康检查）

定期审计 wiki 的质量问题：

| 检查项 | 说明 |
|--------|------|
| frontmatter 合规 | 每个非保留 `.md` 有非空 `type`（OKF §11 硬性要求）；`sources[].resource` 存在。完整清单见 `schema-design.md` 的「OKF 合规自检清单」 |
| 版本声明 | bundle root `index.md` 未声明 `okf_version` 时提示补上（OKF §12） |
| 信任标注 | 无 `verified` 的页面（unverified）建议补验证 |
| 过期内容 | `stale_after` 已过的页面；`status: deprecated` 但仍有活跃引用的页面 |
| 矛盾 | 页面之间存在冲突的论断（标注来源日期） |
| 孤立页面 | 没有入链的页面 |
| 缺失页面 | 多个页面提及但尚未独立建页的概念 |
| 断裂引用 | 分两档：指向已删页面的链接（应修复）；指向未建成概念的链接（建议建页，OKF 容忍断链） |
| 数据缺口 | 可通过网络搜索补充的缺失信息 |
| 建议 | 推荐接下来应该研究或摄入什么 |

将检查结果记入 `log.md`（`## YYYY-MM-DD` + `**lint**` 引导词）。

LLM 擅长"建议你接下来该研究什么"——这本质上是自动化的知识图谱扩展。

## 操作之间的关系

```
新资料 → [Ingest] → wiki 更新 → 知识累积
                                      ↓
提问   → [Query]  → 答案 ←── wiki 支撑
                      ↓
              有价值的答案 → [反哺] → wiki 新页面
                                      ↓
定期   → [Lint]   → 健康报告 → 修复 + 扩展建议
```

三个操作形成良性循环：摄入丰富 wiki，查询利用并贡献 wiki，检查保证 wiki 健康并指引下一步方向。

## 4. 编译提醒

跟踪 `raw/` 中未被编译的来源数量。判断方式：比较 `raw/` 中的文件与 `wiki/sources/` 中已有的摘要页。

当累积 5 个以上未处理的来源时，主动提醒用户：
> "你有 N 篇未编译的原始资料。建议执行摄入操作来整合它们。"

这避免了 raw 堆积但 wiki 没有更新的情况。

## 5. 结构守护者

在每次写操作（摄入、查询产出、检查）完成后，自动执行轻量结构检查。这不是完整 lint，而是快速校验：

**检查项**：
1. **索引新鲜度** — 比较 `wiki/` 目录中的实际文件数与 `index.md` 的条目数。如不匹配，从文件系统和 frontmatter 重建索引。
2. **孤立文件** — `wiki/` 中存在但未被 `index.md` 收录的 `.md` 文件。发现即补入索引。
3. **缺失目录** — 核心目录（`raw/`、`wiki/`、`raw/assets/`、`wiki/entities/`、`wiki/concepts/`、`wiki/sources/`、`wiki/comparisons/`、`wiki/playbooks/`）不存在时自动创建。
4. **日志存在性** — 确认 `log.md` 存在，不存在则创建。
5. **frontmatter 合规** — 发现缺 `type` 的非保留 `.md` 文件，补 `type` 或报告。

**行为规则**：
- **干净时静默** — 一切正常不需要报告
- **小问题自动修复** — 缺失索引、孤立文件等，修复后在 log.md 中记录
- **大问题警告用户** — 结构性错误（内容放错目录等）告知用户并建议执行完整 lint
- **不阻塞用户请求** — 检查完成后继续执行用户原始操作

## 6. 经验教训（Lessons Learned）

当一次会话中出现以下模式时，提取结构化经验：

- 错误→修复循环（摄入时发现的问题和解决方式）
- 用户对 LLM 输出的修正（说明 schema 或模板需要调整）
- 意外发现（跨资料的关联、矛盾、新洞察）

提取流程：
1. 扫描当前会话中的修正和发现
2. 写入 `raw/notes/` 目录（raw 属不可变区，但笔记是人为策划产物；若该目录不在 bundle 内则无需 frontmatter 合规）——如放入 `wiki/` 需遵循 OKF 五大家族并补 `type`
3. 可选：更新相关 wiki 文章以反映新认识
4. 可选：建议将经验提炼为 schema 规则

## 交叉引用原则

交叉引用是 wiki 质量的核心，每次摄入和更新时都必须遵守：

1. **每个页面底部都要有来源引用**，用 footnote keyed to `sources[].id` 指回来源摘要页，确保可溯源。
2. **新资料导入时主动检查已有页面**——新案例应补充到已有实体页，而非只创建新页面。
3. **摘要页末尾列出"相关概念"**，形成概念网络。
4. **标注跨资料关联**：当多篇资料提到相似观点时，在页面中明确标注（如"与 [相关页面](../concepts/xxx.md) 的共同主题：..."）。
5. **链接用相对路径**（如来源摘要页中的 `../entities/xxx.md`），确保普通 Markdown 渲染器可打开；移动页面时同步更新链接。

> 更多关联发现技巧，参阅 `practical-tips.md` 的"知识关联发现"章节。
